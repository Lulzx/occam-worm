## Deliverable

Strict sensory/neural/muscle/body interfaces and baseline checks using a reference physics engine.

## Done when

A fixed, predeclared neural program can be connected without rewriting simulator semantics, and decoder-only controls run.

## Progress

- [x] Typed interfaces for §13.3 (`SensoryInput`, `MotorOutput`, `BodyStep`, plus `NeuralStepper` for the frozen program). Records validate shape, finiteness and ranges; a mismatched connector raises `InterfaceError`.
- [x] Reference body: a planar segment chain under resistive-force theory. Muscles set target curvature through a first-order lag integrated exactly. Head velocity and turning rate solve the force/torque balance exactly. Tests: a head-to-tail wave swims forward, a reversed wave swims backward, a standing wave gives no net progress, net drag force is zero to 1e-15, zero drive stays at rest.
- [x] Motor output fixed from the NMJ edges of a declared reconstruction (Cook 2019), with no fitted parameters. Sign comes from the annotated transmitter (GABA-only inhibitory, ACh without GABA excitatory). Neurons of unclear sign are excluded and listed in the provenance; saturation is flagged per joint.
- [x] Closed loop (sensors → program → muscles → body → sensors) and open-loop replay. A fixed program is connected only through `NeuralStepper.step`.
- [x] Controls: decoder-only (a travelling wave with no neural input, which swims on its own, the §13.5 caveat made concrete) and randomized neural input. Behaviour endpoints: speed, forward fraction, curvature-wave frequency and wavelength.

Code lives in `python/occamworm/embodiment/`. The reference engine is a small, deterministic, low-dimensional body for interface and control checks; validated physics (BAAIWorm, M7) and a stepper adapter for WRL programs connect through the same protocols.
